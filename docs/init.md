# Starter benchmark generation

`zkperf init [DIRECTORY] [--force]` creates `zkperf.toml` and a `benchmarks/`
directory containing a workload specification, input and expected-output
fixtures, and a mock adapter descriptor. The default destination is `.`.
The command never prompts and needs no network access or installed adapter.

The manifest uses explicit v1 policies and fixed bytes, with no timestamps,
random identifiers, absolute paths, or environment-derived settings. Its
single SHA-256 case hashes the three bytes `abc` to a raw 32-byte digest.
Generated manifests are tested with the production manifest loader so schema
changes cannot silently invalidate the starter.

Before writing, initialization checks every template destination. Any existing
template file causes an I/O error (exit 4) with a `--force` hint. With `--force`,
only regular template files can be replaced; unrelated files remain untouched.
Directories at file destinations and symlinks at template destinations or at
`benchmarks/` are rejected even with force. The explicitly selected root may be
a symlink to a directory. Replacing a file breaks its hard links instead of
modifying other linked files. Files are created exclusively to avoid silently
overwriting a destination that appeared after the initial check.

Filesystem failures include the affected path and return exit 4. Initialization
is not a transaction: a failure during writing may leave a partial starter.
The manifest is written last. Re-run with `--force` after correcting the cause.

Success prints the manifest location and a `zkperf validate --manifest ...`
command as the next action. `zkperf run --print-config` also accepts the generated
manifest. Benchmark execution and the mock executable are pending issues #9–15;
the adapter descriptor names `zkperf-adapter-mock`, which must be installed
before execution becomes available. No benchmark results are generated by init.

Verification covers schema compatibility, fixture contents, deterministic bytes
across destinations, default and nested destinations, closed stdin, conflicts
before mutation, forced replacement, unrelated-file preservation, symlinks,
hard links, and CLI diagnostics and next-action output.
